# Refiesse Fit Mini App — MVP ТЗ

**Дата:** 2026-07-08
**Статус:** черновик к утверждению (Эд/Катя)
**Направление:** Soft System — мягкая система движения, не каталог упражнений.
**Владелец документа:** Hermes Orchestrator + Product/UX Agent

---

## 1. Цель MVP

Дать пользователю Telegram Mini App, который **быстро подбирает мягкую тренировку под состояние тела** и показывает ценность системы (планы, каталог, прогресс), с готовой архитектурой под будущий Tribute-доступ.

MVP считается достигнутым, когда сквозной beta-flow работает на реальных данных и реальной оплате:

```text
/start → открыть Mini App → Home → Подбор → Каталог → Карточка тренировки
→ Paywall → Tribute → Доступ открыт → Прогресс
```

Продуктовые критерии успеха:
- пользователь не ищет тренировку по постам/ленте — он выбирает состояние и получает практику;
- free-пользователь проходит полный путь и отмечает «Я сделала» с сохранением прогресса;
- premium-контент закрыт до оплаты и открывается автоматически после Tribute;
- тон продукта — спокойный wellness, без fitness-агрессии, без токсичного streak, без медицинской анкеты.

## 2. Роли пользователей

| Роль | Описание | Доступ |
|------|----------|--------|
| **Гость / free-пользователь** | Открыл Mini App из бота, прошёл онбординг | Home, подбор, каталог (метаданные всех + контент free), free-тренировки, прогресс, профиль |
| **Premium-пользователь** | Оплатил подписку через Tribute, активная `Subscription` | Всё free + premium-каталог, мини-планы, premium-видео |
| **Admin / контент-менеджер (Катя)** | Управляет контентом и подписками | Админка: CRUD тренировок/планов, free/premium toggle, просмотр пользователей/подписок/Tribute events, manual grant/revoke |

Идентификация пользователя — по `telegram_user_id` из подписанного Telegram `initData`. Отдельной регистрации нет.

---

## 3. Основной beta-flow

```text
1. /start в @refiessefit_bot
2. Кнопка/menu button открывает Mini App
3. Home «Сегодня»: тренировка дня + текущий план + CTA «Подобрать тренировку»
4. Подбор (onboarding 4 шага): состояние → время → инвентарь[] → режим
5. Каталог, отфильтрованный под подбор
6. Карточка тренировки: факты, осторожности, видео
   - free → «Начать» / «Я сделала»
   - premium → Locked → Paywall
7. Paywall: ценность Premium → «Открыть через Tribute»
8. Tribute payment link → оплата → возврат в Mini App
9. Webhook Tribute открывает доступ → Success «Доступ открыт»
10. Прогресс: «Я сделала» пишет запись, метрики обновляются
```

## 4. Экраны и acceptance criteria

Экраны основаны на текущем React-прототипе (`apps/miniapp/src/App.tsx`). AC описывают целевое MVP-поведение (на реальных данных), а не текущий mock.

### 4.1 Home «Сегодня»
- **Есть:** бейдж доступа, «Что нужно телу сегодня?», CTA «Подобрать тренировку», категории (Спина/Осанка/Кор/Расслабление), тренировка дня, текущий план.
- **AC:**
  - бейдж доступа показывает реальный статус (`Доступ открыт до <дата>` для premium / нейтральный текст для free) — не хардкод «18 июля»;
  - тренировка дня и текущий план приходят с backend;
  - клик по категории открывает каталог с активным фильтром;
  - CTA открывает онбординг с первого шага;
  - есть состояния loading / error(retry) / empty.

### 4.2 Подбор / Onboarding (4 шага)
- **Шаги:** состояние (`goal`), время (`time`), инвентарь (`equipment`), режим (`intensity`); прогресс-бар 1/4…4/4; кнопка «Назад» на шаге 1 ведёт на Home.
- **AC:**
  - **шаг «инвентарь» — мультивыбор** (`equipment: string[]`), остальные — single choice;
  - выбор сохраняется в профиль пользователя и переживает сессию;
  - последний шаг ведёт в каталог, отфильтрованный по подбору;
  - блок «Подбор» отражает все выбранные значения.

### 4.3 Каталог
- **Есть:** «Найти по состоянию», поиск, чипы (Все / 5–10 мин / Premium / Новичкам), карточки тренировок.
- **AC:**
  - карточки приходят с backend (seed из content matrix);
  - чипы и подбор реально фильтруют список;
  - поиск фильтрует по названию/цели/категории (может быть отложен, но заглушка убрана или помечена disabled);
  - premium-карточка ведёт в Locked/Paywall, free — в карточку тренировки;
  - состояния loading / error / empty.

### 4.4 Карточка тренировки (Workout Detail)
- **Есть:** видео, название, описание, факты (мин / инвентарь / уровень), блок осторожностей, «Начать тренировку», «Я сделала».
- **AC:**
  - все поля из модели `Workout`;
  - free-видео играет в Telegram iOS/Android; premium-видео недоступно без доступа даже прямым запросом к API;
  - «Я сделала» пишет `ProgressEntry` и ведёт в прогресс/показывает подтверждение;
  - блок осторожностей всегда виден.

### 4.5 Plans / Планы
- **Есть:** «Идти по системе», карточка активного плана с прогрессом, premium-план.
- **AC:**
  - планы и дни (`Program` / `ProgramDay`) с backend;
  - прогресс плана (`N/M`) считается по выполненным дням;
  - premium-план ведёт в Paywall при отсутствии доступа.

### 4.6 Locked / Premium закрыт
- **Есть:** приглушённое видео, факты, paywall-блок «Откройте доступ», CTA «Открыть через Tribute».
- **AC:**
  - показывает метаданные тренировки, но **не** контент/видео URL;
  - CTA ведёт в Paywall;
  - при наличии доступа экран не показывается (сразу карточка).

### 4.7 Paywall
- **Есть:** «Refiesse Fit Premium», ценность, список «что входит», «Открыть через Tribute», «Продолжить бесплатно».
- **AC:**
  - «Открыть через Tribute» ведёт на **реальный** payment link (env), не на mock success;
  - «Продолжить бесплатно» возвращает в каталог;
  - тексты из content matrix.

### 4.8 Success / Доступ открыт
- **Есть:** «Доступ открыт», рекомендация «С чего начать», карточка плана.
- **AC:**
  - показывается только при подтверждённом доступе (`GET /access`);
  - рекомендация ведёт в реальный план.

### 4.9 Прогресс
- **Есть:** «Даже 10 минут считаются», метрики (тренировки / минуты / дни подряд / план), «Я сделала тренировку».
- **AC:**
  - метрики считаются на backend из `ProgressEntry`;
  - повторное «Я сделала» за тот же день не задваивает запись;
  - тон без наказаний: пропуск не «обнуляет» с осуждающим текстом.

### 4.10 Профиль
- **Есть:** имя/Telegram, статус подписки, «Управлять подпиской», «Изменить подбор».
- **AC:**
  - имя из Telegram `initData`;
  - статус подписки и `expires_at` реальные (для premium);
  - «Изменить подбор» открывает онбординг с сохранёнными значениями;
  - «Управлять подпиской» ведёт в Tribute (для premium).

## 5. Модели данных

Детальная схема — задача Tech Lead (`docs/tech/data-model.md` + Prisma). Здесь — состав и ключевые связи для MVP.

| Модель | Ключевые поля | Связи |
|--------|---------------|-------|
| **User** | `telegram_user_id` (uniq), `first_name`, `created_at`, `onboarding` (goal/time/equipment[]/intensity) | 1—N Progress, Favorite; 1—1 Subscription |
| **Category** | `slug`, `title` | 1—N Workout |
| **Workout** | `title`, `goal`, `duration_min`, `level`, `equipment: string[]`, `is_premium`, `video_url`, `description`, `cautions`, `category_id` | N—1 Category; N—M Program (через ProgramDay) |
| **Program** | `title`, `days_total`, `is_premium` | 1—N ProgramDay |
| **ProgramDay** | `program_id`, `day_index`, `title`, `workout_id?` | N—1 Program, Workout |
| **ProgressEntry** | `user_id`, `workout_id`, `completed_at`, `duration_min` | N—1 User, Workout |
| **Favorite** | `user_id`, `workout_id`, `created_at` | N—1 User, Workout |
| **Subscription** | `user_id`, `status`, `expires_at`, `tribute_subscription_id` | 1—1 User |
| **TributeEvent** | `event_id` (uniq, idempotency), `type`, `payload`, `signature_ok`, `processed_at` | связь по `telegram_user_id` |

Правила:
- `equipment` — **массив** (мультивыбор в онбординге и в тренировке);
- content matrix (S0-5) — источник полей `Workout`;
- доступ определяется активной `Subscription` (`status=active` и `expires_at > now`), не полем на User.

## 6. API routes (контракт MVP)

Детализация — Tech Lead (`docs/tech/architecture.md`). Базовый набор:

| Метод | Route | Назначение | Доступ |
|-------|-------|-----------|--------|
| GET | `/health` | healthcheck | public |
| GET | `/me` | профиль текущего пользователя + onboarding + статус доступа | auth |
| PUT | `/me/onboarding` | сохранить результат подбора | auth |
| GET | `/catalog` | список тренировок (фильтры: category, duration, premium, level) | auth |
| GET | `/workouts/:id` | карточка тренировки (premium-контент только при доступе) | auth |
| GET | `/plans` | планы + дни + прогресс | auth |
| GET | `/plans/:id` | детали плана | auth |
| POST | `/progress` | отметить «Я сделала» (idempotent по user+workout+день) | auth |
| GET | `/progress` | метрики и история | auth |
| POST | `/favorites` | toggle избранного | auth |
| GET | `/access` | статус доступа (free/premium, expires_at) | auth |
| POST | `/api/tribute/webhook` | Tribute события (проверка подписи) | signature |
| — | `/admin/*` | CRUD контента, пользователи, подписки, events, grant/revoke | admin |

Правила ответов:
- единый JSON-формат ошибок `{ error: { code, message } }`;
- premium endpoint без доступа отдаёт метаданные, но не `video_url`/контент;
- запрос без валидного `initData` → 401.

## 7. Telegram auth

- Фронт получает `initData` из Telegram WebApp SDK и шлёт его в API.
- Backend проверяет подпись `initData` по bot token (HMAC-SHA256 по документации Telegram), проверяет `auth_date` на свежесть.
- По `telegram_user_id` находит или создаёт `User` (idempotent).
- Сессия: JWT (короткоживущий) либо проверка подписанного `initData` на каждый запрос — решение Tech Lead.
- **AC:** невалидная/просроченная подпись → 401; валидный initData создаёт пользователя один раз; есть тесты на верификацию.

## 8. Tribute future integration

- Env-плейсхолдеры: `TRIBUTE_API_KEY`, `TRIBUTE_WEBHOOK_SECRET`, `TRIBUTE_PAYMENT_LINK`.
- Webhook `/api/tribute/webhook`: проверка `trbt-signature`, обработка `new_subscription` / `renewed_subscription` / `cancelled_subscription`.
- Idempotency по `event_id` (лог в `TributeEvent`); duplicate/retry безопасны.
- Связь события с пользователем по `telegram_user_id`.
- Отмена не отрубает доступ раньше `expires_at`.
- Ручной reprocess события из админки.
- **AC:** невалидная подпись → 403 и событие не применяется; после оплаты доступ открывается автоматически; тесты на 3 типа событий + duplicate. (Реализация — Спринт 3.)

## 10. QA checklist (MVP)

Beta-flow (обязателен для релиза):
- [ ] `/start` открывает бот; menu button открывает Mini App;
- [ ] Home грузится с backend, состояния loading/error/empty работают;
- [ ] онбординг: 4 шага, инвентарь — мультивыбор, подбор сохраняется;
- [ ] каталог фильтруется, free/premium разведены;
- [ ] free-тренировка: видео играет, «Я сделала» пишет прогресс без задвоения;
- [ ] premium-тренировка недоступна без доступа (в т.ч. прямым API-запросом);
- [ ] paywall ведёт на реальный Tribute link;
- [ ] после тестовой оплаты webhook открывает доступ → Success;
- [ ] duplicate/retry webhook безопасен; отмена не рубит доступ раньше срока;
- [ ] прогресс и метрики корректны;
- [ ] профиль показывает реальный статус подписки.

Устройства: Telegram iOS + Android (обязательно), Desktop (по возможности). Автоматизация: Playwright по free-flow (Спринт 4).

## 11. Что НЕ входит в MVP

- Соцфункции, комментарии, лента, чат;
- сложная геймификация и агрессивный streak;
- медицинская анкета / диагностика;
- рекомендательный ML-подбор (подбор — детерминированные фильтры);
- мобильные нативные приложения (только Telegram Mini App);
- мультиязычность (только RU на старте);
- расширенная аналитика/CRM (базовые метрики запуска — Growth, Спринт 4);
- напоминания и push-кампании бота (later);
- offline-режим и скачивание видео.
