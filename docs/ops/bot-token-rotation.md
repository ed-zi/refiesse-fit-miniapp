# S0-7 — Перевыпуск токена бота (СРОЧНО)

**Приоритет:** высокий — токен бота был прислан в чат, то есть **скомпрометирован**.
**Ответственный:** Эд (владелец бота) + DevOps Agent.
**Статус:** ждёт действия Эда (агент не имеет доступа к BotFather).

---

## Почему это нужно сделать

По полной сводке проекта токен `@refiessefit_bot` был отправлен в переписку. Любой, кто видел чат, может управлять ботом (читать сообщения пользователей, менять menu button, рассылать от имени бота). Старый токен нельзя считать секретом.

## Что сделать (инструкция для Эда)

1. Открыть **@BotFather** в Telegram.
2. `/mybots` → выбрать `@refiessefit_bot` → **API Token** → **Revoke current token**.
3. Скопировать новый токен. **Не отправлять его в чат/переписку/issue/PR.**
4. Проверить, что старый токен больше не работает (любой запрос к Bot API со старым токеном должен вернуть 401).

## Куда положить новый токен

- Локальная разработка: в `apps/bot/.env` (файл в `.gitignore`, в git не попадает), переменная `BOT_TOKEN`.
- CI / production: в **GitHub Secrets** (repo → Settings → Secrets and variables → Actions) и/или в секретах хостинга (Railway/Render — см. `docs/tech/architecture.md`), переменная `BOT_TOKEN`.
- **Никогда** не хранить токен в коде, в docs, в `vite.config.ts`, в клиентском бандле (фронт токен бота не использует).

## Проверка после ротации

- [ ] старый токен отозван (возвращает 401);
- [ ] новый токен только в env/secrets, поиск по репозиторию по токену/`BOT_TOKEN=` не находит значений;
- [ ] `@refiessefit_bot` `/start` открывает Mini App;
- [ ] menu button ведёт на актуальный URL Mini App.

## Связанные env-переменные

`BOT_TOKEN` также используется backend'ом для верификации Telegram `initData` (см. `docs/tech/architecture.md`, раздел Telegram auth). После ротации обновить значение во всех окружениях (dev/staging/production), иначе auth сломается.
